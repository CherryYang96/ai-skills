# 02-解读规则与归因

> 解读经营数据时的操作规范和质量标准，按质量层次分层。
> 从下往上：先过基本规则 → 再过及格线 → 力求优秀。

---

## 📋 基本规则（Basic Raw）

> 最底层的操作规范，不是分析技巧，是数据处理不犯技术错误的基础。

### R1｜正负号决定涨跌，不能用相对大小判断

- 正值（+）= 增长/涨；负值（-）= 下降/跌
- 负数中"跌幅较小"**不能说"涨"**，只能说"跌幅相对较小"
- ❌ 错误：甜点领涨（-9.39%）
- ✅ 正确：饮品逆势正增长（+6.85%）表现最佳；甜点（-9.39%）与美食（-9.41%）同步下滑，跌幅相近

### R2｜品类对比：找真正的正增长项作亮点

- 多品类对比时，亮点必须是**正值**，不能把"最小负值"当亮点
- ❌ 错误：甜点（-9.39%）领涨品类
- ✅ 正确：饮品（+6.85%）是唯一正增长品类，其余品类均下滑

### R3｜时间口径对齐后再比较

- DoD/WoW/MoM/YoY 用途不同，不能混用
- 含春节的月度数据必须采用农历对齐（见 01-指标口径.md）
- 节假日效应必须用相同节假日结构的基期对比（如对比去年同周）

### R4｜M值必须区分订单M值和实付M值

- 两个口径含义不同，不能说"M值"而不注明哪种
- 引用X看板M值时需注明"CR2区间化月售折算，存在一定数据偏差"

### R5｜拼单功能（请替换为实际功能名）和主站数据分开看

- 合并看会掩盖拼单功能侧的竞争问题
- 分析M值异动时，必须分别呈现拼单功能和主站数据

## 🚫 红线（不合格）

> 出现以下任何一条，解读作废。

### 红线1｜补贴指标用词错误（业务负责人校准）

- **严禁**使用「美团C端折扣率」「网络折扣率」「B端折扣率」等自造名词
- 必须使用专有指标名：「消费C端外卖BU补贴率」「消费B端外卖BU补贴率」「消费外卖BU补贴率」
- 详见 01-指标口径.md 第三节

### 红线2｜补贴孤立解读（业务负责人校准）

- **单独解读补贴率高低无意义**
- 补贴必须联动经营规模（订单量、GTV）分析：
  - 「补贴率↑ + 订单量↑」→ 投入有效，可点名说明
  - 「补贴率↑ + 订单量未增/下滑」→ 需归因，属于异常信号
- ❌ 错误示例：「消费C端外卖BU补贴率 6.15%，WoW +0.98pp」（孤立陈述，无意义）
- ✅ 正确示例：「消费C端外卖BU补贴率 WoW +0.98pp，伴随订单量 WoW +6.01%，补贴投入带动规模增长，效率正常」

### 红线3｜同一维度结论自相矛盾（业务负责人校准）

- **同一份日报中，对同一维度（如全国KA）的结论不得对立并列**
- ❌ 错误示例：同时写「全国KA拖累供给侧」和「全国KA订单增长尚可」
- ✅ 正确做法：选定一个主结论，其他数据作为支撑或修饰
  - 若 KA WoW 为正：「全国KA表现稳健（WoW +6.24%），略低于整体增速但无明显拖累」
  - 若 KA WoW 为负：「全国KA订单下滑（WoW -X%），是供给侧主要拖累」

### 红线4｜使用禁用词

- **「品客效率」不是合法指标名，禁止使用**
- 品客相关合法表述：
  - ✅「品客商家在线数」（`pinhf_poi_online_num`）
  - ✅「品客商家单店日均单量」（`pinhf_poi_avg_ord_num`）
  - ✅「品客交易商家数」（`pinhf_txn_poi_num`）

## ✅ 及格（核心指标解读）

> 能正确识别关键变量并说出"是什么"。达到此标准，解读才算合格。

### 及格标准

**必须覆盖以下三类核心指标，且每类至少给出一个明确结论**：

**① 规模类**（订单量/GTV/客单价）
- 明确说明：整体涨跌方向 + 与全国大盘对比
- 示例：「日均订单量 MoM +3.2%，高于全国直营大盘+1.8%」

**② 流量转化类**（DAU/转化率/频次）
- 明确说明：DAU变化方向 + 转化率是否同向
- 注意：DAU和转化率方向可以相反（天气差时DAU↑，转化率↓）

**③ 竞争类**（M值/补贴比/流量比）
- 明确说明：实付M值和订单M值各自的趋势
- 分析M值异动必须同时看**流量比**和**补贴比**（只看其中一个不及格）

### 典型及格示例

```
3月订单量 MoM +2.1%，与全国大盘持平；实付GTV MoM +3.5%，客单价小幅提升。
DAU MoM +1.8%，转化率基本稳定（环比-0.1pp）。
实付M值 47.2%，较上月-0.8pp；订单M值 41.3%，较上月-1.2pp。
流量比从1.45升至1.51，补贴比维持1.25左右，M值下滑主要由流量比拉升驱动。
```

## ⭐ 优秀（深度归因）

> 在及格基础上，能拆到细分维度，说出"为什么"，给出可操作判断。

### 优秀标准

**在及格三类指标基础上，至少做到以下两点**：

**① 细分维度拆解**（按品类/价格带/用户层）

- 品类拆解：美食/饮品/甜点/快餐各自表现，找出驱动项或拖累项
- 价格带拆解：哪个价格段M值/订单变化最大（关注15-30元中间价格带）
- 用户层拆解：新客/老客/高频用户贡献，尤其关注高频用户的频次变化

**② 归因：明确驱动因素 + 排除干扰**

M值归因必须走完三步：
```
第一步：看M值趋势（订单M值 + 实付M值）
第二步：拆解三要素（流量比 → 补贴比 → 供给比，按影响量级排序）
第三步：定位具体价格带/品类的异动，给出操盘建议
```

GTV/订单量归因公式：
```
GTV = 订单量 × 客单价
订单量 = DAU × 转化率 × 频次
     = 营业商家数 × 动销率 × 单产
```
分析时从**用户视角**和**供给视角**都看一遍，两个视角结论一致才算验证充分。

**③ 识别伪信号，只报真驱动**

- 天气正常但数据异动 → 天气不是主因，找真正驱动因素
- 季节性因素（如秋奶、春节）必须在解读中剥离
- 节假日效应必须说明（旅游城市春节期间异地DAU是结构性增量，非经营能力提升）

### 典型优秀示例

```
M值下滑-0.8pp，主因是流量比从1.45升至1.51（R²=0.81，影响更大），
补贴比维持1.25基本持平（贡献有限）。

品类拆解：饮品正增长（+6.85%）为唯一亮点，美食/快餐均下滑。
快餐简餐订单MoM -4.2%，是拖累总量的主要品类（历史上贡献61%流失）。

价格带：20-30元区间M值下滑最明显（-1.5pp），对应竞对平台爆红包集中打击区间。

用户层：高频用户（6次+/月）频次MoM -0.3次，是隐性风险信号。

建议：优先加补20-30元快餐品类，保护高频用户频次，
15元以下不需要大力加补（M值已在30%以上警戒线安全范围）。
```

## 归因框架速查

### M值归因（三要素优先级）

| 要素 | 影响力 | 判断方向 |
|------|--------|---------|
| 流量比（竞对平台/MT DAU） | ⭐⭐⭐ 最大 | >1.5 且持续升高是主要风险 |
| 补贴比（竞对平台/MT单均补贴） | ⭐⭐ 次要 | >1.4 进高危区 |
| 供给比（商家数之比） | ⭐ 参考 | 接近1说明供给差距收窄 |

### GTV/订单归因矩阵

| 分析维度 | 拆分方式 | 关注重点 |
|---------|---------|---------|
| 品类×工具场 | 饮品/正餐/快餐×拼单功能/主站/神券 | 哪个品类在哪个场域异动 |
| 价格带 | 0-15/15-20/20-30/30-60/60+ | 哪个价格段变化最大 |
| 用户层 | 新客/老客/沉默/高频/黑金 | 哪类用户贡献增量/减量 |
| 供给类型 | KA/CKA/A级城商 vs 长尾 | 优质供给vs长尾差异 |

### 收补期归因注意

- 收补2周内DTU下滑约[X%]是正常幅度（参考值，请根据本城市历史校准），超过需关注
- DAU下滑拆解：[示例值]%用户直接不再进站（贡献[示例值]%DAU下滑，请用本城市数据校准） + [示例值]%进站不下单
- 收补期分析基期选择：**相同长度的稳定基期**（不含特殊节假日）

## 操盘建议参考（收补/竞争阶段）

> 解读输出"可操作判断"时，对照此节选取建议方向，而非凭空生成。

### 四象限人群精细化操盘（1月目标城市实证）

**维度构建**：单用户ROI × 高价订单浓度（30元+订单占比）

| 象限 | 特征 | 操盘建议 |
|------|------|---------|
| 一象限 | 高ROI × 高价单浓度 | **优先加补**（贡献53%增量订单） |
| 二象限 | 低ROI × 高价单浓度 | 观察，条件改善后加补 |
| 三象限 | 高ROI × 低价单浓度 | 维持现状 |
| 四象限 | 低ROI × 低价单浓度 | **回收补贴** |

**效果实证**：ROI升至[示例值]，人均GMV +[示例值]%，单均实付价 +0.14元

**核心逻辑**：补贴精准度 > 补贴总量。一刀切降补贴会损伤一象限高价值用户，四象限回收补贴是释放资源的最优先方向。

### 分工具操盘逻辑（收补敏感性参考）

| 工具/场域 | 主要偏好用户 | 收补敏感性 | 操盘建议 |
|----------|------------|-----------|---------|
| **免费神券** | 流失风险用户偏好（使用占比34.7%） | ⭐⭐⭐ 高，收补后流失多 | 收补需同步配合召回策略，不能单独收 |
| **付费券包** | 降频用户偏好，忠诚度更高 | ⭐⭐ 中，降频但不流失 | 优先维持水位，是锁定用户的最有效工具 |
| **拼单功能（请替换为实际功能名）** | 低价客群，但与目标城市用户画像适配度低 | ⭐ 低 | 兜底作用有限，不作为主要防守工具 |
| **爆红包/神券场** | 中低价格带（15-20元）用户 | ⭐⭐ 中 | 关注竞对爆红包力度，优先在此区间对位 |

**关键原则**：
- 不能因为神券用户流失高就优先召回神券用户——效率低；优先转化"访问降频用户"效率更高
- 付费券包用户是最值得保护的群体，即使收补期也不应大幅削减其权益

## ⭐ 优秀层：跑赢/跑输大盘后的归因分析框架

> 来源：业务负责人指示。这是解读质量从「及格」到「优秀」的核心跨越。
> **不能只报「跑赢了X pp」就结束**，必须沿以下链路继续追问。

### 核心逻辑链（订单/GTV 跑赢大盘时）

```
Step 1: 目标城市订单/GTV WoW 跑赢全国大盘？（差值 = 目标城市WoW - 全国WoW）
    ↓ 是
Step 2: 流量（DAU = fin_usr_num）有没有同步增长？
    │
    ├─ 【流量涨了】
    │   Step 3a: 流量质量怎样？
    │     → 用户分层结构变化：成熟用户占比↑/↓？过渡用户↑/↓？尝鲜用户↑/↓？
    │     → 成熟用户占比提升 = 结构优化（好信号）
    │     → 尝鲜用户大涨 = 可能有活动拉新，需观察留存
    │   Step 4a: 流量是什么驱动的？
    │     → 外部因素：天气指数 weather_index_value 明显为正？（天气利好）
    │     → 内部因素：美补率↑（net_mt_disc_rate↑）or 商补率↑（poi_disc_rate↑）？
    │     → 结论模板：「流量增长主要由[天气/美补/商补]驱动，用户结构[优化/未优化]」
    │
    └─ 【流量没涨，或涨幅远小于订单涨幅】
        Step 3b: 转化率（访购率 trans_rate_gmv）是否提升？
          → 访购率↑ = 同样流量买得更多，转化效率提升
        Step 3c: 老客频次是否提升？
          → 老客订单量（餐饮老客 fin_ord_num）WoW↑，但老客用户数没变 → 频次提升
          → 结论模板：「订单增长来自存量用户挖掘（老客频次↑/转化率↑），非新增流量」
```

### 跑输大盘时的反向诊断（同样适用）
- 流量下滑 → 天气差？补贴收缩？竞对加大力度？
- 流量没跌但订单跌 → 转化率下滑？老客流失？
- 结构性恶化信号：尝鲜用户占比持续↑ + 成熟用户占比↓ = 用户质量下降，需预警
